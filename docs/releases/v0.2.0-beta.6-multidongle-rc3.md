# OrcSDR v0.2.0-beta.6 Multi-Dongle RC3

RC3 is an experimental test release. It replaces RC2 for multi-dongle testing
but remains unmerged and is not a stable OrcSDR release.

## What changed since RC2

- Pins `esp-rtl-sdr` commit `26e3857cb6a2cc7c09a7197ce07c46c29becd4e0`.
- Prevents the driver from reusing USB transfers still owned by the USB host
  after a drain timeout.
- Reworks AM station scanning to retune through all 119 channels at the normal
  sample rate instead of allocating a large wideband capture.
- Always shows the AM scan save/discard result prompt, including when zero
  stations are found, then restores the previous AM frequency and audio.
- Caps RF analysis to the IQ samples actually present, preventing an
  out-of-bounds read and task-stack corruption.
- Aligns the connected Wi-Fi regression with the supported radio-pause path.

## Blog V4 acceptance

On the tested RTL-SDR Blog V4, AM scanning completed all 119 channels, showed
the result prompt, restored 1.280 MHz and audio, and produced zero driver USB
overruns and zero consumer drops. Wi-Fi reconnect/scan, catalog verification,
location lookup, dashboard transitions, gain controls, retuning, and repeated
USB reconnect testing also passed. Bias-T remained off for the connected
MLA-30+ setup.

## Provisional receivers

- RTL-SDR Blog V3 remains experimental.
- Nooelec NESDR SMArt V5 remains experimental.
- Both may stream only at 24 MHz or above unless their reported capabilities
  say otherwise. Unsupported HF and controls remain blocked.
- Build success is not reception acceptance. Test with an antenna suitable for
  the selected band and report the exact receiver, frequency, antenna,
  waterfall/audio result, and a complete cold-boot serial log.

The published RC2 image pinned older driver commit `8cc5bbb`; RC3 is the first
published OrcSDR candidate containing the tested USB-drain fix.

- OrcSDR source: this release tag
